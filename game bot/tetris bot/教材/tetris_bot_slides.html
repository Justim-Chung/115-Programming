PART 2｜小問題 ③

drop_row()：一列一列往下試，停在最後放得下的那列

從最上面開始，每次只往下一列；再往下就放不下時，目前的列就是落點。

虛線是 T 形的落點：左上角在 row = 18。

row = 0 ～ 17：都 ✓
row = 18：✓
row = 19：✗ 超出底部
回傳 row = 18
# 一開始連 row = 0 都放不下 → None
def drop_row(board, shape, col):
    if not fits(board, shape, 0, col):
        return None
    row = 0
    # 再往下一列還放得下，就繼續往下
    while fits(board, shape, row + 1, col):
        row += 1
    return row                 # 最後放得下的那一列

注意：row 記的是方塊左上角所在的列，不是方塊的底部。之後的評分會受到這一點影響。

PART 2｜小問題 ⑤

count_holes()：數一數被蓋住的空格

洞 = 同一欄裡，上面已經有方塊的空格。

紅色的 4 格是洞：它們的上方都有方塊。
第 3 欄與第 6～9 欄沒有洞。

holes = 4
# 逐欄檢查
def count_holes(board):
    holes = 0
    for col in range(COLS):
        covered = False                  # 這一欄上面有方塊了嗎？
        for row in range(ROWS):          # 由上往下看
            if board[row][col]:
                covered = True
            elif covered:                # 空格且上方有方塊 → 洞
                holes += 1
    return holes

洞一旦形成，就要先消掉上面的方塊才能補上，之後的方塊更難放，所以我們要扣分。

PART 2｜小問題 ⑥

choose_move()：把所有可能都試一遍，留下最高分

以 T 方塊為例，共有 34 種放法。

① 方向：T 有 4 種（0°、90°、180°、270°）

② 欄位：寬 3 的方向有 8 個欄位，寬 2 的方向有 9 個

③ 每一種：落下 → 放置與消行 → 算分 → 記住最高分

8 + 9 + 8 + 9 = 34 種
# 逐一試放，記住最高分
def choose_move(board, piece):
    best = None
    for turns, shape in enumerate(rotations(SHAPES[piece])):
        for col in range(COLS - len(shape[0]) + 1):
            row = drop_row(board, shape, col)
            if row is None:
                continue
            after, cleared = place_and_clear(board, shape, row, col)
            score = row + 100 * cleared - 50 * count_holes(after)
            if best is None or score > best[0]:
                best = (score, turns, col, row, after)
    return best

同分怎麼辦？程式用 > 而不是 >=，所以保留先遇到的放法。

PART 3｜評分的設計

分數 = 列號 + 100 × 消行數 − 50 × 洞數

先看懂每一條規則想解決什麼問題，之後再來質疑它。

分數 = 落點列號 + 100 × 消行數 − 50 × 洞數
消行數 × 100

消一行，盤面就少一行

這是最直接的好處：消掉的列不再佔空間，也就降低了之後的風險。權重最大。

洞數 × −50

洞會讓以後更難放

洞被上方的方塊蓋住，要先清掉上面才能補。所以每多一個洞，就扣 50 分。

落點列號 × 1

鼓勵放低，不要太早堆高

列號越大代表位置越低。同樣能放的情況下，比較低的位置比較安全。

權重的大小關係：100 ＞ 50 ＞ 1。消行的價值，大於避免洞；避免洞的價值，又大於「放低一點」。這些數字是教學用的手動設定，不是標準答案。

PART 3｜評分的設計

用數字看分數：消行與洞的影響最大

以下是兩種假設的放法，數字只用來說明計算方式。

放法 A

落在最下層（row = 19），消 1 行，0 個洞

19 + 100 × 1 − 50 × 0 = 119

放法 B

落在 row = 17，不消行，2 個洞

17 + 100 × 0 − 50 × 2 = −83

A 比 B 高出 202 分。一行的獎勵，就能蓋過許多「放低」或「少洞」的差異。

想一想：如果另一種放法是 row = 19、不消行、0 個洞，分數是 19。它只比 A 少 100 分——這個差距，你覺得合理嗎？

PART 3｜先別急著相信它

這樣算，真的最好嗎？

下面四個問題，請先猜答案，再按一下看解說。

問題 1

水平的 I 與垂直的 I，都落在最底層，分數一樣嗎？

不一樣。列號取的是形狀的左上角。水平 I 的 row = 19；垂直 I 有 4 格高，左上角是 row = 16，少了 3 分。

問題 2

一個盤面很平，一個凹凸很多，只要消行與洞數相同，分數會不同嗎？

一樣。分數完全沒有考慮「高低起伏」，也沒有鼓勵盤面保持平整。

問題 3

100、50 是怎麼來的？改成 100 與 10 會怎樣？

是人手設定的權重。改了數字，同一盤面就可能選出不同的放法。好不好，要靠實際玩來比較。

問題 4

程式讀了 NEXT，評分時有用到它嗎？

沒有。choose_move 只看目前這一塊；NEXT 只用來安排時序，沒有參與比較。

幾種計分方式的比較

沒有哪一組權重永遠最好。重點是知道每個特徵在「管」什麼。

計分方式核心想法優點缺點
目前的教學版列號 + 100 × 消行 − 50 × 洞簡單好懂，會消行，也會避免洞不看平整度；列號取的是左上角；權重靠手動調整

貪心很簡單，但它不知道下一塊會是什麼。

為每一種放法算分

y = 左上y + (row + 0.5) × 格子大小
rgb = image.getpixel((x, y))[:3]
board[row][col] = 0 if sum(rgb) <= 140 else 1
1 量：盤面左上、右上 → 格子大小 = 距離 ÷ 10
2 定位：取每一格的中心，避開格線與邊緣
3 取色：三色加總 ≤ 140 視為黑色（空格）
4 轉換：黑色記為 0，其他記為 1；整個盤面重複 200 次

PART 4｜接上遊戲

NEXT 是哪一塊？用顏色投票

七種方塊各有一個代表色。掃描 NEXT 框內的像素，票數最多的顏色，就是下一塊的種類。

I 形（青色）
O 形（黃色）
L 形（橘色）
S 形（綠色）
Z 形（紅色）
T 形（紫色）
J 形（藍色）
① 每隔一個像素取樣一次，掃過 NEXT 的整個矩形。
② 每個像素和 7 個參考色比距離；夠接近，就替那個顏色投一票。
③ winner = max(votes, key=votes.get)：票數最多的顏色就是答案。
④ 票數不到 10 票，回傳 None 並停止。寧可停下，也不要猜。

PART 4｜接上遊戲

把決定翻成按鍵：先轉、再移、最後落下

例：T 方塊轉 2 次，放在第 5 欄。START_COLS 記錄每個方向的起始欄位。

① 旋轉

按 ↑ 兩次，旋轉到 180°。

② 水平移動

distance = 5 − START_COLS['T'][2] = 5 − 3 = 2
所以按 → 兩次。

③ 落下

按空白鍵，方塊直接落到底。

# 先轉、再移、最後落下
def send_move(piece, turns, col):
    for _ in range(turns):
        pyautogui.press("up")            # 旋轉
        time.sleep(KEY_DELAY)
    distance = col - START_COLS[piece][turns]
    for _ in range(abs(distance)):
        pyautogui.press("right" if distance > 0 else "left")
        time.sleep(KEY_DELAY)
    pyautogui.press("space")             # 直接落下

按鍵之間的 KEY_DELAY 讓遊戲來得及接收。遊戲若有位移或特殊旋轉，結果可能與預期不同，所以要再檢查一次。

PART 4｜對帳

為什麼要對帳？試算不等於遊戲真的發生

程式只能「假設」按鍵成功。每次操作後，都要再看一次畫面，確認結果。

原因 1

按鍵沒有被接收

遊戲沒有鍵盤焦點、按得太快，或按鍵被忽略。

原因 2

動畫還沒結束

消行動畫或落地動畫會讓取樣點變色，所以按完先等 SETTLE_DELAY 秒。

原因 3

方塊還在上方下落

最上面 4 列可能是正在落下的方塊，比對時先忽略（TOP_ROWS_TO_IGNORE）。

做法：最多重拍 RETRY_COUNT 次，每次隔 RETRY_DELAY 秒；只要有一次與試算一致，就繼續。
設計的想法：對帳失敗時，程式寧可停下來，也不要在錯誤的盤面上繼續亂按。

補充素材｜評分特徵

評分可以看的特徵，除了洞與消行，還有很多

先介紹其中 3 個，其餘的請同學自己發想。

越小越好

總高度 Aggregate height

每一欄最高方塊的高度，全部加總。放在不平的地方，總高度會增加得更多。

越小越好

凹凸度 Bumpiness

相鄰兩欄高度差的總和。盤面越平整，數字越小。

經典

井 Wells

兩側都比較高的窄坑。4 格深的井，直放的 I 可以一次消 4 行；但若被 O 蓋住，就變成 4 個洞。

其餘 6 個特徵，請同學發想

例如：行轉換、欄轉換、落點高度、消去的方塊格數。提示：先想一想「好的盤面」長什麼樣子，再把它變成數字。
